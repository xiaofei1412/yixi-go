# 弈习产品路线：从对弈复盘到学习闭环

[返回项目首页](README.md) · [模型训练路线](README-train.md)

产品面向围棋爱好者，以训练和棋后复盘为主。已按顺序完成四阶段功能开发和 Windows 启动器迁移修复，当前进入用户试用前的阶段性收尾。

这份文档将逐轮开发记录整理为功能演进、使用方法与验收说明。产品使用本地 KataGo Analysis Engine；自行训练的学生模型是独立实验路线，尚未接入产品。

快速导航：[阶段顺序](#开发顺序与产品目标) · [安装与迁移](#后续修复启动器迁移与安装使用) · [数据维护](#数据代码与本地维护) · [验证记录](#验证记录与复查命令)

## 开发顺序与产品目标

最初的讨论把项目分为训练实践和应用开发两条路线。产品路线随后先行推进：先让对弈与复盘可靠，再把复盘中的问题变成能重下、能保存、能复习的学习记录，最后提供变化之间的直接对照。

| 顺序 | 阶段目标             | 已完成的结果                                                           |
| ---- | -------------------- | ---------------------------------------------------------------------- |
| 1    | 建立对弈与复盘基础   | 多棋盘尺寸、规则、结算、自动存档、SGF 树、分支试下、分析缓存与推荐回放 |
| 2    | 让复盘进入下一次练习 | 精选学习点、独立重下、预计损失反馈、笔记与固定间隔复习                 |
| 3    | 看见自己的学习记录   | 统计、手动知识点标签、待巩固回顾、筛选与历史                           |
| 4    | 比较不同选择的后续   | 实战/重下/推荐三栏，记录与推演切换，同步回放、差异与提子               |
| 5    | 解决换电脑启动失败   | 探测解释器、保留并重建失效虚拟环境，补充迁移步骤                       |
| 6    | 与训练实践并行归档   | 复用规则与引擎通信，业务继续由 KataGo 提供分析，训练结论另行维护       |

## 第一阶段：对弈、棋谱与复盘基础

### 实现与设计取舍

围棋规则、SGF 树与引擎通信从页面交互中分开：`go_game.py` 负责棋盘和分支，`katago_service.py` 管理本地引擎，`server.py` 提供 API 和 SQLite 保存。前端由同一服务提供，避免把直接打开 HTML 当作完整启动方式。

引擎按需启动，以请求 ID 匹配返回结果，限制并发并处理退出、超时。分析结果保存在本地，更深搜索可供较低预算请求复用；缓存与引擎/模型/配置文件标识关联。产品分析使用独立配置，不覆盖原训练路线的配置。

### 对弈与复盘操作

- 新对局可选 9、13、19 路，执黑或执白，以及自由让子。让子时默认白贴 0.5，可自行调整。
- 对手思考与复盘精度分别设置，数值代表搜索次数上限，不代表段位。
- 对局自动保存。刷新后恢复当前棋局；如果轮到 AI，可点击“继续对弈”。左侧保留最近 100 盘棋的入口。
- 进入复盘后，棋局转为自由分析模式，不再自动触发 AI。原有棋谱保留。每次在历史局面试下都会保留已有后续为其他分支。
- 方向键、进度条和分支按钮均可浏览；点击候选列表，使用左右按钮逐手回放推荐变化。回放采用实际提子和劫判断。
- `examples/review-demo.sgf` 是功能演示棋谱，包含批注与两个分支，可直接导入。它不是教学定式。
- 导出将当前选定分支放到主线，同时保留其他变化和批注。棋谱导入支持自身声明的字符编码（例如 UTF-8、GBK）。
- “全谱初筛”只分析当前分支，按每局面 100 次搜索串行执行；停止后不再提交下一局面，已经发出的单次搜索仍会完成。结果存入本地，后续更低预算会复用已有较深结果。
- 走势统一为黑方目差。曲线下的突变节点仍只是回看线索；第二阶段的“精选学习点”会另外复核实战落点后再收录。系统尚不提供自动棋理归因。

### 规则与结算边界

新对局使用中国数子方式：全局同形禁着、禁止自杀、无额外让子补偿，白方贴目由开局设置决定。后端与引擎使用相同的显式规则。

双方连续停着后进入结算。点击棋子会整块标记死子，由确定性的数子逻辑计分；领地预测只用于分析，不用于宣称确定胜负。死活仍需使用者确认，双活中的活棋应保留；有争议可继续对局。

SGF 支持 9/13/19 路、根节点摆子、正常落子及完整分支、批注。导入的 Chinese 规则按上述产品规则解释；Japanese/Korean 使用单劫规则进行回放和对应 KataGo 分析，但本阶段不提供日/韩规则终局结算。未声明规则时默认 Chinese，未声明贴目时使用中国规则 7.5、日/韩规则 6.5。

暂不支持其他规则名称、中途增删棋子或改变执棋方、多盘合集；不支持时返回明确错误。单文件最大 2 MB、最多 3000 个节点。复杂裁判规则与自动判死活不在本阶段范围内。

## 第二阶段：从复盘到重下与复习

这一阶段把分析线索变成独立练习。核心工程问题是防止作答前泄露答案、避免重复提交重复计次，以及保证原棋谱后续变化不会改变已经收录的题目。后端保存局面快照和可重试的提交记录，前端增加独立练习窗口、坐标输入、批量进度与停止入口。

### 快速体验

1. 导入 `examples/study-demo.sgf`。这是人工构造的功能演示局面，不是标准棋理教材。
2. 保持在第 1 手之后，点击“精选学习点”中的“复核刚下的一手”。首次启动引擎需要稍候。
3. 点击左侧“学习中心 · 错题与复习”，打开刚收录的练习。独立选点，再点击“提交这一手”。
4. 查看预计损失，用左右按钮逐手回放推荐变化，写下笔记并点击“保存笔记”。需要继续研究时，点击“回原局面对照分析”。
5. 以后从“待复习”继续；“全部练习”可提前重温。练习与原棋谱分开保存，不会在原棋谱中落子或新增分支。

### 从自己的棋谱精选

- 进入复盘，选定需要研究的分支，先完成“全谱初筛”。
- 在“精选学习点”选择黑方、白方或双方，再点击“精选本分支”。界面默认双方；想只复习自己的棋，应选择自己的执棋颜色。
- 初筛按落子方视角寻找预计损失至少 2 目的线索，最多挑选 6 个局面，所选节点至少相隔 3 个节点，避免集中在连续几手。
- 随后串行复核，单次最多新增 3 道练习。初筛仅完成一部分时会提示覆盖情况；未发现可靠学习点时不强行生成题目。
- “停止精选”会在当前局面的复核结束后停止后续请求，当前已完成的收录仍保存。重复精选会复用已有练习，保留笔记和复习进度，并继续寻找尚未收录的局面。
- 也可导航到某手棋之后，点击“复核刚下的一手”，直接复核该手；无需先做全谱初筛。起点及纯批注节点不能作为已落下的一手收录。

### 判定标准

收录时先在落子前局面进行 400 次搜索预算的分析，再以同一局面、同一规则、同一执棋方，限制根节点只搜索实战落点进行复核。比较的是两次搜索返回的候选 `scoreLead`，统一换算为落子方视角；搜索噪声设置为 0。接口依据 [KataGo Analysis Engine 官方说明](https://github.com/lightvector/KataGo/blob/master/docs/Analysis_Engine.md)。

- 推荐候选与受限搜索候选均至少需要实际搜索 100 次，否则本次不收录、不判分，可重试。
- 实战落点相对保存的推荐落点预计损失至少 2 目才收录；实战本身就是推荐点或损失较小则跳过。
- 练习作答后，推荐点与原实战点复用本题已保存的评估；其他合法落点使用 400 次预算的受限根节点搜索。预计损失不超过 1 目视为通过，因此其他效果接近的下法也可通过。
- 预计损失的负值按 0 处理，表示本次评估未发现比参考落点更差。界面显示参考与作答落点的实际搜索次数。
- 棋盘支持点击选点，也可输入坐标（如 D4，列号跳过 I）后选点；“选择停着”属于一次正常作答。“看答案”明确记录为看过答案，不计通过。
- 提交前不返回推荐落点、原实战落点、分析数值、棋谱批注或个人笔记。练习窗口遮住复盘内容；提交后可看答案、笔记及推荐变化，再返回原局面查看批注。
- 非法落点、引擎离线或搜索不足不会产生完成记录，保留本次练习以便重试。对同一次提交重试不会重复计次；重新打开同一道题会使此前未完成的练习会话失效。

上述阈值是本地学习工具的启发式标准。两次有限搜索存在波动，400 次预算及 100 次候选搜索门槛并不构成统计可靠性保证；推荐点也不保证是目差最优点。本阶段不宣称精确棋力评分、唯一正确答案、死活证明或自动生成棋理解释。需要判断关键细节时，可回到原局面增加分析精度。

### 错题记录与复习安排

- 每道练习保存独立局面快照、原实战落点、引擎参考、提交结果、个人笔记及复习时间。列表展示上次结果、连续通过次数和下次复习时间。
- 新收录的练习立即进入待复习。到期答对后，按连续通过次数分别安排 1 天、3 天、7 天后复习；此后每次到期答对保持 7 天间隔。
- 未通过或直接看答案：连续通过次数归零，10 分钟后再复习。
- 提前重温时答对，不增加连续通过次数，也不延后原定复习时间。提前练习未通过或看答案，仍按 10 分钟规则重新安排。
- “已完成次数”包含正常提交与直接看答案；关闭未提交的练习不计完成。
- 笔记最多 1000 字，需点击“保存笔记”；作答前隐藏，提交或看答案后展示。时间存为 UTC，界面按浏览器本地时间显示。
- 模型、引擎或配置文件变更并重启服务后，旧练习保留，但不再进入待复习队列；全部练习中会标记不可用。请回原棋谱重新收录，旧笔记不会自动迁移到新题。

本阶段采用固定间隔，不包含自适应记忆算法、知识点自动标签、每日通知或后台持续生成任务。关闭网页会停止提交后续精选请求，已经发出的当前复核仍可能完成并保存。

## 第三阶段：学习中心与知识点回顾

在第二阶段的题目与复习记录上增加学习概览，重点明确统计分母、重复练习的样本数和记录归日。保留旧题与旧作答，新增真实完成时间及标签，并为离开练习时尚未保存的内容提供提示。

### 使用方法

1. 打开左侧“学习中心 · 错题与复习”，查看近 7 天、近 30 天或全部时间的概览；展开“每日练习记录”查看每天通过、未通过和直接看答案的次数。
2. 完成一道练习后，在答案区域选择最多 3 个知识点标签，并点击“保存标签”。可选：布局、死活、手筋、对杀、连接与切断、劫争、官子、形势判断。取消全部勾选并保存即可清除标签。
3. 返回学习中心，在“知识点回顾”查看需要巩固的题目情况。点击某一类会切换到该标签的全部练习；也可自行组合“待复习 / 全部练习”和知识点筛选，“尚未标注”便于整理已有错题。
4. 答题后点击“下一道待复习”，按到期时间继续当前标签下的其他可用题目；不会提前抽取尚未到期的题目，也不会重复当前题。没有其他到期题目时返回列表并提示。
5. 作答后的“本题最近 10 次记录”展示时间、结果、自己的落点和预计损失。标签与历史不会显示在新一题的作答面板中。读取记录失败时，可点击“刷新本题记录”，已经判定的结果仍然保留。

笔记和标签分别保存；关闭练习窗口、返回列表、回原局面或进入下一题时，如有未保存修改，会提示是否放弃。刷新整个网页不属于此保护范围。学习中心的统计和标签整理无需启动 KataGo。

### 统计口径

- **已作答**：实际提交落子的次数，包含通过与未通过；不包含直接看答案、未完成会话或搜索失败。
- **作答通过率**：通过次数 / 已作答次数。没有实际作答时显示“暂无作答”，不会显示成 0%。重复提交同一次练习不会重复计数；重新打开并完成题目属于新的练习，仍会计入作答次数。
- **练过不同题目**：所选时段内有完成记录的不同题目数，包含直接看答案。**有练习的天数**也包含直接看答案。
- **时间范围**：按北京时间（Asia/Shanghai，UTC+8）的自然日统计，近 7 / 30 天均包含今天。选择全部时间时，概览汇总全部记录，展开的每日图仍只展示最近 30 天。
- **完成时间**：第三阶段起记录实际提交完成时间；第二阶段的旧记录没有该字段，沿用练习开始时间近似归日，并在概览和历史中注明。未来时间的记录不计入当前统计。
- **历史范围**：概览保留旧模型的历史练习；待复习列表及知识点回顾只使用当前模型仍可用的题目。统计时段只影响概览和知识点回顾，不限制下方题目列表。

### 知识点回顾的边界

每道题只取所选时段内最近一次完成结果：未通过或直接看答案计为“待巩固”，通过则不计。至少积累 3 道不同题目后，才视为具备回顾样本；反复练同一题不会增加这里的样本数。样本足够的类别优先展示，再按待巩固比例排列；样本不足会明确提示。

标签完全由用户手动标注，属于自己的学习分类，系统不会自动宣称某手属于死活、官子等棋理问题。汇总使用题目当前保存的标签，修改标签会重新归类历史结果；多标签题会分别计入对应类别，所以各类数量不应相加当作独立题目总数。未练习但已标注的题目会出现在类别中，样本数为 0。

这些指标用于回顾学习记录，不是段位评估或棋力提升的证明。第三阶段没有加入自动棋理归因、自定义标签、跨设备同步或新的复习间隔算法；原有 1 / 3 / 7 天安排继续使用。

## 第四阶段：三栏变化对照

这一阶段让用户直接比较不同首手对应的后续，重点区分棋谱中发生的记录与引擎假设推演。新增回放和对照缓存模块；旧练习按需补算，保留原判分与复习进度。

### 使用方法

1. 在学习中心打开一道练习，提交自己的落点，或选择“看答案”。作答前不开放变化对照。
2. 在答案区域点击“对照实战、重下与推荐变化”，展开三个棋盘。桌面并排显示，小屏幕按纵向排列。
3. 实战栏默认显示“棋谱记录的后续”，也可切换为“该落点的引擎推演”；另两栏分别显示自己的重下落点之后的引擎应对，以及引擎推荐变化。
4. 使用起点、左右按钮或进度条同步逐手回放。每栏独立显示已回放手数、最后落点或停着、累计黑白提子数；较短的变化停在末尾并注明，不会补造后续。
5. 勾选“标出与推荐线的差异”时，橙圈标出各栏与推荐栏当前画面棋子分布不同的交叉点。可以关闭标记，差异数量仍然显示。
6. 点击“收起对照”返回常规练习阅读，笔记和标签保留；再次展开复用当前结果。进入新一题时清空旧对照，避免提前看到答案。

快速体验仍可使用 `examples/study-demo.sgf`：收录并完成练习后展开对照。该演示谱只有一手后续，因此棋谱栏会较早到达末尾；切换为引擎推演后可以继续比较。只看答案而没有提交落点时，“我的重下”栏明确显示无作答，不生成虚构选择。

### 数据来源与解释边界

- **棋谱后续**来自收录学习点时保存的棋谱及选定分支，保留非主线选择，跳过纯批注节点。如果当时选择的是用户试下分支，这一栏也会回放该分支，不代表真实比赛记录。收录后再浏览、试下或切换原棋谱，不会改变该学习点的快照。
- **引擎推演**使用收录或作答时保存的候选变化。实战落点与自己的作答落点，其后续均是假设双方继续按引擎推荐行棋，不是实际发生过的棋谱。
- **目差与预计损失**仅对应共同起点处的首手候选分析。同步回放不会逐帧重新分析，也不应把固定显示的目差误读为每一帧的新评估。目差统一显示黑方视角，损失沿用原题或原作答判定。
- **差异标记**只比较当前展示棋盘的交叉点内容，不代表得失目、领地变化或棋理原因。短线已结束时与长线显示的手数可能不同，界面会标明各线进度。
- **提子数**从共同起点累计，并非整盘棋的总提子。回放复用现有规则实现，处理提子、禁自杀与劫；遇双方连续停着时停止，不自动判死活或终局计分。
- 每条线最多展示 12 手；超长、连续停着、后续落点无法合法回放或保存的变化首手不一致时，会明确提示，并仅展示能够确认的部分。分析本身未提供后续时，可能只有首手。

本阶段仍不提供逐步棋理讲解、自动因果归因、三栏自由试下、变化导出或更高预算的对照重算。主复盘页面原有自由试下功能继续保留。

### 旧练习兼容与保存

第四阶段起，新的作答结果同时保存自己的候选变化，因此通常无需额外搜索即可生成三栏对照。旧记录若作答与原实战或推荐相同，复用当时的参考；如果是其他落点且缺少保存的变化，仅在首次打开对照时补做一次受限根节点搜索，并缓存结果。

旧作答补算可能与原判分的目差不同，界面会标明“旧作答补算”。它不会覆盖原判分、完成时间、作答次数、笔记或复习安排。搜索失败不保存空缓存，可以重试。模型或引擎配置变化后不会继续使用旧对照，请重新收录并完成练习。

## 后续修复：启动器迁移与安装使用

换电脑后报 Python 路径错误，核查发现原因是复制的虚拟环境仍引用旧电脑的 Python 安装位置。修复把“文件存在”检查改为“解释器实际可运行”检查：有效环境复用；无效环境先保留，再使用本机 Python 重建。无需手工改写个人绝对路径。

### 本机启动

双击根目录 `start-product.cmd`，保持启动窗口开启，再在浏览器访问 http://127.0.0.1:8000 。

启动器会实际检查 `.venv` 中的 Python 是否能够运行，并要求 Python 3.10 或更高版本；不再仅判断 python.exe 文件是否存在。正常环境直接复用；失效环境保留为 `.venv.unusable-随机数-随机数`，随后优先使用本机 `py -3`、其次使用 PATH 中的 `python` 重新创建 `.venv`。缺少产品依赖时会自动安装 `requirements-product.txt`，首次安装需要联网。若本机没有可用 Python，则给出安装提示，不移动原有环境。

### 换电脑运行（Windows）

1. 在新电脑安装 Python 3.10 或更高版本，建议使用 64 位版本，并勾选添加到 PATH；也可使用安装程序提供的 `py` 启动器。
2. 复制项目代码、`requirements-product.txt` 以及 `katago_engine` 中的引擎、模型和配置。建议不要复制 `.venv`、`.venv.unusable-*` 和 `__pycache__`，虚拟环境应在目标电脑重新创建。
3. 如需保留棋谱、错题、笔记和复习记录，先停止旧电脑服务，再复制完整 `product_data` 目录。
4. 在新电脑双击 `start-product.cmd`，等待环境及依赖准备完成，再访问页面。即使已经复制了失效的 `.venv`，启动器也会保留旧目录并重建，无需手动修改 Python 绝对路径。

原问题来自 `.venv/pyvenv.cfg` 记录了创建环境的电脑上的 Python 安装位置，而不是启动器写死了个人安装路径。不要通过手改 pyvenv.cfg 来迁移环境；重新创建更稳妥。

本启动器面向 Windows。当前随项目提供的 KataGo 是 OpenCL 版本，新电脑还需要兼容的显卡驱动与 OpenCL 运行环境；Python 环境修复不等于引擎硬件兼容性也已解决。其他操作系统需要替换对应的引擎与启动方式。

### 手动启动

也可以在项目目录执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn server:app --host 127.0.0.1 --port 8000
```

首次安装环境：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-product.txt
```

需要 Python 3.10 或更高版本。产品不依赖训练路径的 PyTorch 或 cgo 扩展。前端由同一个服务提供，不再直接双击 index.html。

KataGo 会在首次需要分析或落子时启动，显卡首次调优可能较慢。当前保留项目已有 v1.16.4 引擎和 b28 模型。`katago_engine/product_analysis.cfg` 单独控制产品分析，原有引擎配置未覆盖。每次搜索最多 25 秒，首次加载及请求总等待最多 90 秒。
